# 核心战斗系统：扩展与验收

当前采用60Hz固定逻辑、ABCD四键、角色化搓招、3格资源和地面连段；第二阶段补齐专属动作与反馈。运行游戏不需要联网或生成新图片。

## 资源入口

`CombatCatalog`通过Godot资源目录发现 `resources/characters/*.tres`，再注册其中引用的招式。重复角色ID、重复且指向不同资源的招式ID会报错。目录使用 `ResourceLoader.list_directory`，可兼容导出后的资源映射。

新增角色的最小流程：

1. 新建 `CharacterDefinition`资源，填写唯一ID、名称、定位、移动速度、颜色、元素名和本地动画目录。
2. `normals`提供 `5A…5D`、`2A…2D`、`jA…jD`；`motions`提供 `236A/C`、`623A/C`、`214B/D`、`super`、`max`；另提供 `throw_move`。
3. 每招指定现有或新增的 `animation_id`，特效用 `effect_id`。动画图集沿用脚底锚点和 `phase_breaks`，不必与招式ID同名。`state_animations` 映射翻滚、前后投、受投和拆投，`MoveData.presentation` 引用独立表现资源。
4. 填写 `move_list`和 `combos`。选人、招式表、表现目录和通用AI自动读取资源。选人卡片可横向滚动。
5. 为新角色加入输入、命中、连段与图集覆盖验收。新类别的招式机制需要扩展通用逻辑；仅新增当前机制内的角色无需修改角色分支。

`tools/build_combat_data.py`是当前42份招式资源的离线作者工具，不是运行依赖。平衡调整可直接编辑tres；需要再运行作者工具时须同步其参数，避免覆盖手工调参。

## 输入和时间约定

公开入口仍为 `Combat.step([p1_command, p2_command])`：

```gdscript
{"x": -1, "y": 0, "buttons": 1 | 2}
# 世界方向 x=-1左、1右，y=-1上、1下
# ABCD持有位分别为1、2、4、8；松开必须在后续帧提交0
```

键盘/手柄层只做物理映射、摇杆滞回和菜单返回时的按住抑制。识别器负责边沿、搓招、双击和组合键。AI也逐帧提交这些数据，不传递招式ID。

- 搓招存相对朝向的方向变化；转身清除未完成方向序列，已确认按下的普通技不会因转身丢失。
- 236/214为30帧，末方向到按键最多12帧；斜方向可省略，末方向仍必须是水平。方向记录包含按住区间，以起始下方向的最后占用帧计时，久蹲可接招；后续方向不能通过长按刷新整段窗口。
- 623维持20帧，双236维持36帧；末方向到攻击维持6帧，623保留斜下方向。
- 攻击可在最后方向前2帧输入；复用组合键等待期间重新识别，只允许升级到更高优先级指令。普通技、组合键原有等待时间不增加；转身禁止未完成指令跨朝向补全。
- 已识别的必杀/奥义/翻滚消费当前方向序列，避免放宽窗口后再次按攻击误出旧必杀。练习诊断保留近90帧方向，提示保留180逻辑帧；这些记录不会扩大实际识别窗口。
- 组合键容差2帧，AB优先处理翻滚，双236+AC优先MAX，然后超杀、623、236/214、方向投、普通技。
- 动作执行缓冲6帧；命中停顿、超杀停顿仍采样输入，但冻结动作缓冲的剩余执行时间。
- 回合、暂停及设备切换清理待执行输入。渲染时间只用于插值和特效；伤害、资源、飞道具和演出停顿由逻辑帧决定。

`DuelFighter.snapshot()`枚举运行变量并将招式资源转换为ID；输入识别器保存方向占用区间、按键、待确认组合、已消费序列界限、双击状态及练习诊断与到期帧。`DuelCombat.snapshot()`另外保存资源继承、投技、飞道具、实例编号、计时和超杀停顿。

## 招式与接触约定

`MoveData`资源在对战中保持不变：

- `startup / active / recovery`为60Hz逻辑帧；`box`从脚底朝右定义，朝左镜像。
- `stance`决定地面/空中使用和落地终止。`cancel_targets`按该招明确列出可取消到的类别；命中确认条件由模型统一执行。
- `hit_frames`定义多段有效区间的起点。空数组代表一段，配置值为整招帧号。`damage`为整招总伤害；`segment_damage(index, scale_percent = 100)`先按倍率计算整招总伤害并向下取整，再均摊到各段，余数计入最后一段。整招修正伤害至少为段数，以保证每段至少1点；只有实际命中的段计入扣血。默认参数保持原始分段伤害，防御削血沿用该调用。
- 每次出招分配唯一攻击实例。每段对每个对手只结算一次；已有n个命中实例时，下一招普通技/普通必杀倍率为 `max(40, 100 - 5 * n)`，即100%、95%、90%……最低40%。超杀和MAX固定100%，完整伤害280/445。实例在首次实际命中时锁定倍率，多段共享；打空和防御不增加该计数。伤害、HUD、命中事件和回气以实际扣血为准，击杀截断到剩余生命。
- `projectile_speed / projectile_lifetime / projectile_box`启用独立飞道具。每名角色同时最多一枚，发射后不依赖角色当前动作；相撞互消，命中或防御后消失。
- `anti_air_until`仅对空中施放者的近身打击生效，不提供对地或防飞道具的全身无敌。
- `meter_cost / freeze_frames`用于奥义。通过全部启动条件后一次扣气；不足时消费该次指令并提示，不回退成其他攻击。

近身攻击、飞道具接触均先收集、后结算，保证双方同帧攻击能够互换。投技最后处理，同帧打击会打断抓取。前后投共用联动框架；7帧拆投窗口接受D的新按下边沿。

连段以对手恢复行动而结束。地面普通技不能重复，轻技最多两招，每种后续类别有次数限制；浮空初次命中之后最多两次追加实例。扫倒、投技和奥义末段负责终结。不能通过HUD的显示倒计时延长连段。

## 验证方法与当前结果

运行 `tests/run_tests.ps1`：输入、战斗、移动、连段、练习、真实UI事件、表现和字体/图集检查；30/60/144渲染帧率分别推进1800个逻辑帧，比较完整快照。

`tests/run_tests.ps1 -Capture`额外生成实际OpenGL截图与1080p性能报告。覆盖960×540、1280×720、1920×1080、两名角色全部招式、练习设置与招式表；没有用绘制的示意图替代引擎截图。

- 连段矩阵每人30条路线，左右朝向×中场/版边共240组、1664项检查。包含原4条示例、裸奥义、各种轻技确认、双轻技、必杀取消与跳入长路线；首击后防检查断连，并核对每招身份、实际扣血、HUD和耗气，报告在 `artifacts/combo-validation.json`。
- 原4条示例当前为：无气下段226/226、跳入274/269、1格495/495、MAX584/582（炭治郎/善逸）。裸MAX445，5A接MAX490、2A接MAX485、2B接MAX472。实测跳入长MAX为774/770，基准生命1000，不加总伤害硬上限。
- `tests/damage_tests.gd`检查整招取整、40%下限、奥义伤害保护、漏段/中断、削血、致死截断、回气和连段重置；通过真实接触结算枚举每人7139种路线形态，整招命中与首段取消两种情况下共115720次扩展比较均有正收益。该数值枚举不证明距离和不断连，真实输入验证由上述240组矩阵负责；汇总在 `artifacts/combo-damage-audit.json`。
- `tools/balance_audit.gd`执行24组种子、每组交换玩家位置，共48场。此次修改前为炭治郎20胜/善逸28胜，修改后24胜/24胜，均无未完成比赛。平均每场逻辑步数2466.29→2222.10（含停顿与局间阶段，约缩短9.9%），双方合计实际伤害4300.85→4268.04、耗气912.5→825；伤害总量受局数和击杀截断影响，不代表单套伤害下降。原始记录在 `artifacts/balance-audit.json` 和 `artifacts/balance-audit-before-combo-damage.json`，对比在 `artifacts/combo-balance-comparison.json`。
- AI统计用于识别偏差，不等同于真人胜率。手柄映射与断连已通过模拟输入验证，尚未连接实体手柄验收。

## 第二阶段表现约定

`CharacterDefinition.state_animations` 负责无招式资源的动作状态。前投与背投分别选择 `throw_forward`／`throw_success`，受方选择 `thrown_forward`／`thrown`；投向保存至受方。拆投的 `reaction` 只读取既有16帧硬直，受击或恢复行动即清除，未添加新硬直。

`MoveData.presentation` 指向 `MovePresentation`：轮廓、颜色、声音和残影数量均为表现数据，战斗判定不读取这些字段。普通技按 `phase_breaks` 将画帧分配至启动／有效／收招。多段动画启用 `segment_sync`，用 `hit_frames` 的真实分段分配各自连续画帧；六连使用六组不同接触姿态，逻辑停顿时当前姿态与残影冻结。取消、受击和重新出招会清除旧残影。

翻滚12张画帧的零基逻辑时间点为 `[0,1,2,4,6,9,12,15,18,20,23,26]`；无敌仍为零基2—17帧，18—19帧落脚，20—27帧为明确收招。前投与受投共用零基20帧落地接触点。脚底、空中骨盆锚点、固定比例与选帧记录在 `calibration.json` 和 `imports/`，不会反向影响判定。

战斗在每段有效区间起点发出一次 `strike`；命中／防御事件携带招式、实例和段号。声音按实际出手和接触事件播放；空挥没有命中音。拆投的兼容 `clash` 事件由表现层去重，耗气与气不足分别提示。多段中间段降低火花、震屏和音量，MAX以局部蓄力环及分层火／雷光增强辨识，双方位置和收招保持可见。

命中停顿和超杀停顿冻结动作与特效时钟；暂停冻结角色、镜头、特效及正在播放的音频。重置清空声音、残影、粒子与提示；回合结束清理攻击表现。`audio.gd` 生成本地可复现PCM；游戏和录像使用同一事件到音色映射。
