# 招式扩展：派生连续技、方向特殊技、空中必杀与空中连携

总体方案见 [moveset-animation-plan.md](moveset-animation-plan.md)。本文记录已经落地的通用机制、炭治郎的新招数据和验证方法。

## 原则

- **默认关闭**：所有新字段的默认值都等于原有行为，没有扩展数据的角色走的仍是原来的代码路径，AI 的随机数序列也不变。引擎改动后，在不修改任何现有测试的前提下完整回归全部通过；84 招的帧数据报告前后逐项一致（`artifacts/frame-data-before.md` 与 `frame-data-after-engine.md`）。
- 沿用现有的 `kind`（light/heavy/skill/super/max/throw），不新增招式类别，因此音效、特效、HUD 和 AI 的分类逻辑不受影响。
- `.tres` 是唯一数据源。检测到扩展字段时，`tools/build_combat_data.py` 和 `tools/build_roster_data.py` 会拒绝运行，避免覆盖手调数据，或把炭治郎的派生复制给猗窝座。

## 数据结构

`DuelMove`（`scripts/move_data.gd`）新增字段：

| 字段 | 默认值 | 作用 |
|---|---|---|
| `follow_ups` | `{}` | 按键 → 派生的下一段招式 |
| `cancel_requires_hit` | `false` | 取消和派生只在命中后生效，被防不行 |
| `landing_recovery` | `5` | 空中招式落地后的硬直帧数 |
| `air_gravity_percent` | `100` | 招式进行中的重力比例 |
| `air_velocity_frames` / `air_velocities` | 空 | 在指定招式帧改写速度（前进, 向下），前进分量按朝向镜像 |
| `projectile_vy` | `0` | 斜向飞道具，落地即消失（留给猗窝座使用） |

`CharacterDefinition` 新增三个字段，原有的 `normals` 和 `motions` 保持 12 个和 8 个键：

- `command_normals`：方向特殊技，键为 `"6B"`、`"3C"` 等；
- `air_motions`：空中必杀，键为 `"j236A"`、`"j214D"` 等；
- `advanced_list`：招式表「特殊技·派生」页的行（方向特殊技、派生连续技、空中连携）。空中必杀和地面必杀一起写在 `move_list` 里，显示在「必杀与奥义」页。

`all_moves()` 先按原顺序列出基础招式，再按广度优先收入派生段，同时去重、防环。

`MovePresentation.landing_clip` 可以为空中必杀指定专属的落地收招片段；不指定时沿用 jump 片段的第 4/5 帧。

## 出招规则（`scripts/combat.gd`）

1. **优先级**：派生 > 近身 6D/4D 投 > 方向特殊技 > 5X/2X/jX。
2. **派生**：
   - 生效条件：当前招式已经接触（命中或被防），按键时没有按下方向；空挥不能派生。
   - 只跳过“按类别取消”这一项检查。同招不能重复、轻技最多 2 次、重技/必杀/超杀各 1 次这些连段限制仍然有效，每一段也照常计入伤害修正。
   - 因此 2B → 5A → A 会被拒绝，因为 A 会是这一串的第三个轻技。
3. **方向特殊技**：只在地面且不在冲刺中时生效，按“相对朝向的方向 + 按键”查表，没有对应条目就退回原来的普通技。随之而来的输入现象：
   - 236+B 会出 6B；搓 236C 失败会出 6C；前走中按 B/C 也会出 6B/6C。
   - 前向特殊技之后立刻搓 236，会被识别成 623（6→2→3→6）。这和街霸的升龙误出是同一类现象，稍晚一点输入即可。
4. **空中必杀**：
   - 生效条件：在空中、离地不少于 20px、这一跳还没用过空中必杀（每跳 1 次）。
   - 不满足时沿用原有行为：落地后在缓冲时间内放出地面版。
   - 在空中被打中后，本次落地前不能再用空中必杀。
5. **空中连携**：
   - 空中招式只能在接触后取消，而且只能取消到 `cancel_targets` 允许的类别。
   - 同一跳里每招最多出现 1 次，最多 3 招（`AIR_CHAIN_LIMIT`）。
   - 浮空追击上限仍是 3 个攻击实例。

招式构成参考了《火之神血风谭》的猗窝座（参考拆解见 [vfx/akaza-reference.md](vfx/akaza-reference.md)）。被防和命中有利帧是在 34px 距离由 `tests/frame_probe.gd` 实测得到的。原有 21 招的数据和已验证连段完全不变；只给 5A 加了派生入口，给 jA–jD 加了空中连携的取消目标。动作暂时借用旧片段，美术 v3 重绘后换成专属片段。

- **万叶闪柳**是浮空击倒：倒地的对手没有受击框，所以末段改为把对手震上半空，超杀和 MAX 才能接上。空挥或被防都不能取消；被防 −8，要靠第二段（−3）停手才安全。

- **空式·下**是飞道具，有利帧取决于距离：贴身（24–50px）被防 −10～−14（重版 −12～−15），70px 左右在 −1～−7；再远气拳到得晚，猗窝座反而先恢复（轻版 90px 处 +7～+10；重版飞得快，要到 110px 才有利，约 +6）。在 34px 以内对蹲着的对手会从头顶飞过，所以“必须站防”在 70px 处测量；飞游星千轮同理在 50px 处测量。
- **按键分配**：B/D 是体术键、A/C 是攻击键（猗窝座的 A/C 是拳，B/D 是腿），所以两脚连踢的流闪群光放 6B，直拳的踏进冲拳放 6C（2026-10-16 交换，招式数据不变）。
- 输入副作用与炭治郎相同：236+B 出 6B，搓 236C 失败出 6C，前走中按 B/C 也会出 6B/6C。

## AI（`scripts/ai_controller.gd`）

新分支都先读取招式数据，所以其他角色的决策和随机数序列不变。炭治郎的 AI 会：

- 5A 命中后以 45% 的概率接派生；
- 空中轻技命中后接空中重技；
- 近距离偶尔出 6B，中距离出 6C；
- 在空中、距离较近时偶尔出泷壶；
- 6B 被防后不再追加必杀；空中必杀之后不接超杀。

平衡审计用 `tools/balance_audit.gd -- --pairs=tanjiro:zenitsu,tanjiro:nezuko,tanjiro:akaza --out=...` 运行：每组对战 24 个种子，交换左右位置，共 48 局。这是 AI 对战的诊断数据，不代表真人胜率；48 局的胜场标准差约为 3.5。

| 炭治郎对 | 改动前 | 改动后 |
|---|---|---|
| 善逸 | 17 / 48 | 26 / 48 |
| 祢豆子 | 19 / 48 | 18 / 48 |
| 猗窝座 | 28 / 48 | 33 / 48 |

AI 的第一版用法会把 8% 的近身 5A 换成头槌，还会频繁出波纹突刺，合计胜场反而降到 58 / 144。改为“头槌只对蹲姿对手、突刺只在对手没出招时少量使用、空中远距离不乱挥”之后，合计 77 / 144（改动前 64 / 144），全部对局都正常结束。原始数据见 `artifacts/balance-audit-before-moveset.json` 和 `artifacts/balance-audit-after-moveset.json`。

## 测试

- `tests/move_expansion_tests.gd`（`MOVE EXPANSION TESTS`）：
  - 注册：去重、防环，发布清单按 id 记录派生；
  - 合成招式验证速度关键帧、重力比例和落地硬直；
  - 派生：命中和被防都能接，空挥不能；不影响原有招式；连段上限照常生效；
  - 头槌的上段判定和“只有命中才能取消”；波纹突刺的远距离判定；各种输入回退；冲刺中保持普通技；
  - 空中必杀：每跳 1 次、低空回退到地面版、落地硬直、只能站防；
  - 空中连携的限制；
  - 实测有利帧；
  - 真实输入的精确伤害。
- 发布验证（`scripts/combat_verifier.gd`）：在原有 `RELEASE COMBAT: 64 cases` 之外，新增根据数据自动生成的 `RELEASE EXPANSION`，覆盖每条派生串和每个方向特殊技（目前 12 例）。`run_tests.ps1` 和 `build-release.ps1` 都要求这两行同时为 0 失败。

## 招式表

帮助页的分页按强度从低到高排列：基础攻防｜普通技｜特殊技·派生｜必杀与奥义。原来的「进阶技」页排在必杀之后，看起来比必杀还强，因此拆开：

- 打潮、头槌、波纹突刺、空中连携放在「特殊技·派生」，示例连段也移到这一页的下方；
- 泷壶和空中水车并入「必杀与奥义」，排在地面必杀之后、超杀之前。这一页超过 5 行时自动缩小行距；超杀和 MAX 的觉醒说明按指令（`236236`，含 `A+C` 的是 MAX）识别，不再依赖行号；
- 对战暂停菜单的「招式速查」同样读取 `move_list`，超过 5 行时缩小行距。
