# 招式扩展 + 角色动画重制：全局方案，炭治郎先行

## 背景
- **招式现状**：四名角色的招式结构完全相同（12 个普通技、236/623/214 轻重版、奥义、MAX、投），普通技连数值都一样。现在没有特殊连续技（派生）、空中必杀和方向特殊技。祢豆子和猗窝座的数据是分别从善逸和炭治郎复制来的，角色个性几乎只体现在外观上。
- **炭治郎画面不一致的根因**（已查明）：
  1. 39 个动作片段是 39 次互相独立的 gpt-image-2 调用，片段之间只靠一张设定图维系，头身比、市松纹尺寸、配色和线宽都没有约束。
  2. CPA 不按请求尺寸出图，固定返回约 1.57MP，各片段只好分别重采样 0.42–1.24 倍，线宽和清晰度因此不一。
  3. 比例靠手调 `calibration.json`，每个片段一个数，没有自动测量头部。觉醒版用包围盒拟合，同一片段内比例最多相差 18.5%。
  4. 没有调色板锁定，羽织绿的中位色在各片段之间漂移（R55–94 / G144–174 / B120–152）。
  5. 游戏里的“待机”其实是一张静止图，外加 ±0.3% 的呼吸缩放（`scripts/presentation/fighter_view.gd:248-251, 341-344`）。
- **已确认的决定**：
  - 不用视频，全部在本地用 CPA 生图完成；
  - 炭治郎所有动作全部重绘；
  - 每人新增约 4 组招式；
  - 现有招式和已验证连段的伤害保持不变；
  - 先做全局框架，再做炭治郎，炭治郎经用户确认后再做下一个角色。

## 总原则
1. **新机制默认关闭**：没有配置新数据的角色，代码路径和 AI 随机数序列都与现在一致。以下结果必须完全不变：64 条真实输入连段、30 条练习连段的伤害、伤害枚举（7139 条路线）、30/60/144 FPS 快照比较。
2. **沿用已有的 `kind`**（light/heavy/skill/super/max/throw）：新增类别会牵动 AI、音效、特效和 HUD，代价太高。
3. **现有片段只换画**：帧数、`phase_breaks`、`segment_sync`、`timeline` 全部保留，所以判定时序、超杀视频的收招帧和回合测试都不受影响。只有待机（改成循环）和新招式的片段是新增的。
4. **美术硬规则**：
   - 每个片段只用一个比例；
   - 比例按头部标尺计算，不按包围盒拟合；
   - 所有片段使用相同的网格和重采样倍率；
   - 颜色按材质锁定；
   - 不合格的帧由质检拦下，不进游戏。

## 一、全局：招式扩展框架（数据驱动）

### 1.1 数据结构
**新招式放进新字典**，不碰 `normals` 和 `motions`。这样 `tests/combat_tests.gd:35`（12 个普通技 / 8 个必杀）的断言和 12 格普通技帮助页都能保持不变。

**`scripts/move_data.gd`（DuelMove）新增字段**，默认值都等于现有行为：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `follow_ups: Dictionary` | `{}` | 按键 → 派生的下一段 |
| `cancel_requires_hit: bool` | `false` | 为真时，取消和派生只在命中后生效，被防不行 |
| `landing_recovery: int` | `5` | 替换 `combat.gd:690` 里写死的 5 |
| `air_gravity_percent: int` | `100` | 招式进行中的重力比例 |
| `air_velocity_frames: PackedInt32Array` 与 `air_velocities: PackedVector2Array` | 空 | 在指定帧改写速度，x 按朝向镜像 |
| `projectile_vy: float` | `0.0` | 斜向飞道具，给猗窝座用 |

**`scripts/character_definition.gd` 新增字段**：
- `command_normals`（键 "6B"/"6C"/"3C"）
- `air_motions`（键 "j236A"/"j236C"/"j214B"/"j214D"）
- `advanced_list`（帮助页的行）

`all_moves()` 改为广度优先遍历，把派生段也收进来，并做去重和防环。这样 `CombatCatalog`、所需动画片段、发布清单都会自动包含新招式。

**`scripts/fighter_state.gd` 新增**：`air_chain: Array[String]`、`air_specials: int`。快照会自动带上这两个字段。

### 1.2 出招判定（只改 `_choose_move` 和 `_try_action`，在 `scripts/combat.gd:539-605`）
- **优先级**：派生 > 近身 6D/4D 投 > 方向特殊技 > 5X/2X/jX。
- **派生**：
  - 生效条件：当前招式已经接触（命中或被防，空挥不行）、按键时没有按下方向、按键在该招的 `follow_ups` 里。
  - 只跳过按类别取消的检查（L563）。同招禁止重复、轻技最多 2 次、重技/必杀/超杀各 1 次这些限制仍然有效。所以 2B→5A→A 会被拒绝，伤害枚举的范围不变。
  - 每一段都是新的攻击实例，伤害修正照常递减。
- **方向特殊技**：只在地面、非冲刺时生效。键值由 x（相对朝向）和 y 计算，y<0 不生效。
  - 副作用（写进文档并加测试）：236+B 会出 6B；搓 236C/623C 失败会出 6C；前走中按 B/C 也会出 6B/6C。
- **空中必杀**：同时满足以下条件时，`_choose_move` 取 `air_motions["j"+指令]`：
  - 角色在空中；
  - 这一跳还没用过空中必杀（每跳 1 次）；
  - 离地不低于 20px。

  否则沿用现有行为：落地后在缓冲时间内放出地面版。L567 只对 `stance=="air"` 的必杀放行。在空中被打后，本次跳跃不能再用空中必杀。
- **空中连携**：
  - jA/jB 的 `cancel_targets` 设为 `["heavy","skill"]`，jC/jD 设为 `["skill"]`。
  - 新增限制：同一跳里每招最多 1 次，最多 3 招（`AIR_CHAIN_LIMIT`）。
  - 浮空追击上限仍是 3 个实例（L745），总伤害有上限。
- **空中物理**：
  - `_advance` 在招式帧上按设定改写 vx/vy。
  - `_integrate` 只在比例不等于 100 时改变重力，旧招式的运算完全不变。
  - 落地分支使用 `landing_recovery`，并清空 `air_chain` 和 `air_specials`。
  - 起跳和 `begin_cinematic_tail` 也清零这两个值。
  - KO 慢放的 `_outro_skill_motion` 同步应用速度设定。
- **专属落地动作**（展示用，可选）：落地时记录 `f.landing_move`。`MovePresentation.landing_clip` 存在时，`fighter_view` 用它代替 jump 的第 4/5 帧（泷壶落地的 19–23 帧硬直需要专门的收招画面）。
- **发布清单**：`combat_verifier.resource_snapshot()` 把“值为 Resource 的字典”转换成 `{键: id}`。
- **防误改**：`tools/build_combat_data.py` 和 `tools/build_roster_data.py` 在检测到扩展字段时拒绝运行，否则会覆盖新数据，或把炭治郎的派生复制给猗窝座。

### 1.3 AI（`scripts/ai_controller.gd`）
新分支都先检查角色数据，其他角色的决策和随机数序列不变。
- **命中确认**（L68-79）：
  - 5A 命中后，45% 概率按 A 进入派生；派生第二段属于轻技，现有规则会接着按 C，打出第三段。
  - 空中轻技之后按 C，接空中重技。
  - 带 `cancel_requires_hit` 的招式被防后，不再跟必杀。
  - 空中必杀之后不接超杀。
- **立回**（L98-113）：
  - 近距离时按小概率出 6B；
  - 中距离（66–118px）时出 6C；
  - 空中只在距离小于 120 时按小概率出空中必杀，其余情况出 jC。

## 二、全局：招式设计规范与平衡

### 2.1 招式槽位（每人约 4 组，参考拳皇/街霸）
| 槽位 | 规则 |
|---|---|
| 特殊连续技（派生 2–3 段） | 空挥不能派生，派生段计入轻/重技名额。总伤害约等于同起手的常规路线；末段被防 −5～−9，需要取消必杀才能安全。 |
| 方向特殊技（1–2 个） | 中段技（上段判定）发生不少于 17F，可以看反应防住，被防 −4～−6，只有命中时可以取消。长距离戳刺贴身被防约 −9，尖端打中则安全。 |
| 空中必杀（轻重版） | 每跳 1 次，只能站防。被防后落地 −5～−14，打点越高越吃亏；命中击倒。 |
| 空中连携 | 轻 → 重 / 必杀，同一跳里每招 1 次，最多 3 招。 |

### 2.2 伤害上限（1000 生命）
- 无气不超过 23%；
- 1 格不超过 42%；
- MAX 不超过 52%。

常见无气路线仍保持在 14–18%。新增内容提供的是更多选择，不是更高伤害。

### 2.3 平衡验证
- **新增 `tests/frame_probe.gd` 和 `tools/frame_data_report.gd`**：输出 `artifacts/frame-data.md/.json`，列出每招的发生 / 持续 / 收招 / 伤害 / 硬直 / 被防有利（公式值和实测值）/ 取消 / 派生 / 落地硬直。空中招式分别在第 12、20、26、30 跳帧采样。
- **伤害枚举**：在新路线形态上检查“追加一招必定增加伤害”。
- **`tools/balance_audit.gd`**：改动前先保存 `artifacts/balance-audit-before-moveset.json` 作为对照，改动后重新跑。验收标准：
  - 炭治郎 48 局赢 18–30 局；
  - 没有未完成的对局；
  - 平均时长变化在 ±15% 以内。

## 三、全局：美术管线 v3（各角色通用，炭治郎先用）

### 3.1 流程与对策
**流程**：定稿 → 生成 → 处理（抠像 / 头部标尺 / 调色板锁定 / 锚点）→ 质检门禁 → 打包图集 → 烘焙觉醒版 → 重建刀刃轨迹 → 审阅

| 根因 | 对策 |
|---|---|
| 各片段独立生成 | 每次生成都带同一组参考：**已确认的待机关键姿势 + v3 设定图**。超过 6–8 帧的片段分批生成，后一批额外带上前一批的结果作为参考。 |
| 返回尺寸不一，重采样倍率各不相同 | 一律请求 **1536×1024**，正好等于服务实际返回的尺寸。宽动作用 3×2 网格（每格 512×512），窄动作用 4×2 网格（每格 384×512）。提示词写死绝对像素标尺：头顶到脚底约 430px，头长按定稿测得。这样所有片段的重采样倍率都约为 0.79，线宽一致。 |
| 比例靠手调 | 新增 `anatomy.py`：用发色和肤色掩膜自动估算头部（取面积的平方根，不受旋转影响），每个片段取中位数，得到唯一的比例。遮挡和翻转帧写进人工复核表，做法同 `tools/awakening_anatomy.calibrated_frames`。 |
| 颜色漂移 | 新增 `palette.py`：从定稿图提取各材质的标准色（羽织绿/黑、绛红衣裤、白色绑腿、发色、肤色、刀身）。在 Lab 空间按材质归类，然后**整张图统一**向标准色做均值/方差迁移（不逐帧做，避免闪烁）。 |
| 持刀状态混乱 | 姿势表逐片段写明刀的状态：战斗片段一律双手持刀，只有开场和胜利动作的特定帧收刀。 |

### 3.2 工具（`tools/art_v3/`，按角色参数化）
- `spec/<角色>.json`：参考图、标尺、标准色、各片段的网格、刀的状态、背景色。炭治郎用品红 #ff00ff，因为羽织是绿色。
- `poses/<角色>.json`：逐帧的姿势描述。现有片段按旧帧整理，帧序号保持不变。
- `prepare.py`：仿照 `tools/prepare_nezuko_awakening_v8.py` 的写法（逐帧姿势说明 + 像素标尺 + 参考图）生成任务清单和提示词，同时生成旧帧的“灰色人偶节奏图”（只提供姿势和节奏，不带旧画风和旧比例）。
- **生成**：直接用 `tools/run_roster_art_job.ps1 -Id <id> -Manifest output/imagegen/tanjiro-v3/jobs.json`。它会写请求记录，已有请求不会重复发送，也不自动重试。
- `process.py`：复用 `tools/process_anime_art.py` 里的以下函数：
  - `cutout()`：品红抠像 + 边缘反混合；
  - `sprite_components()`；
  - `foot_anchor()`；
  - `save_atlas_page()`；
  - `process_clip` 中的脚底/骨盆锚定逻辑。
- `idle_warp.py`：生成待机循环，见 3.3。
- `awaken.py`：觉醒版由普通版逐帧派生，身体像素完全相同，只在额头烘焙「斑纹」贴图。斑纹位置由头部检测得出，个别帧用人工覆盖表修正。觉醒版的帧数、偏移和阶段划分与普通版一致，不需要额外生图。
- `pack.py`：沿用 `process_anime_art.pack()` 的打包方式，输出 `atlas.json`、`round-atlas.json`、`awakening/atlas.json`，修订号为 `tanjiro-v3`。
- `review.py`：联系表（叠加头部标尺和地面线）、GIF、指标汇总 HTML，输出到 `artifacts/art-v3/<角色>/`。
- **来源记录**放在 `output/imagegen/tanjiro-v3/`，包括：
  - `references/`、`prompts/`、`raw/`、`records/`、`imports/`；
  - `selected.json`、`acceptance.json`、`authorization.json`。
- **重绘完成后**：
  - 重新运行 `tools/build_blade_tracks.py tanjiro`，普通版和觉醒版都要跑；
  - 清空 `tools/blade_overrides/tanjiro.json` 后重新复核。

### 3.3 待机动画
- **关键姿势**：用 CPA 生成 3–4 个候选，由用户选定。约束：剪影高度与现有待机一致（约 323px），以保持 `fate_revision_tests` 里各角色的身高关系。
- **补间**：由 `idle_warp.py` 离线完成。
  - 方法：在网格上做移动最小二乘（MLS）形变（numpy 实现），再用 `cv2.remap` 重映射。
  - 控制点（`spec/<角色>-idle-rig.json`）：
    - 脚底固定；
    - 胸肩随呼吸起伏；
    - 双手和刀身作为整体小幅抬落；
    - 羽织下摆和发梢按相位滞后摆动；
    - 膝部轻微屈伸。
  - 输出：12 帧、10fps，约 1.2 秒一个循环，首尾无缝衔接。
- **运行时**：
  - 在图集的 idle 片段上加 `"cycle": true`。`clip_metadata` 会原样保存 JSON，所以加载器不用改。
  - `fighter_view.gd` 读到这个标记时按 fps 循环播放，并关掉程序化呼吸。没有标记的角色保持现状。
- **各角色方向**：
  - 炭治郎：水之呼吸中段架势，双手持刀，刀尖斜指对手，屈膝，神情沉稳；
  - 善逸：低位居合，闭眼睡态，轻微摇晃；
  - 祢豆子：低伏的野性架势，弹跳较快；
  - 猗窝座：前手立掌、后手握拳，脚尖轻跳。

### 3.4 其他角色的美术深度
每个角色动工前，先用 v3 的质检指标（头部比例离散度、配色 ΔE、重采样倍率范围）给现有图集打分，再决定是全量重绘，还是只做待机 + 新招 + 不合格片段。善逸和炭治郎出自同一条旧管线，预计问题类似；祢豆子和猗窝座出自 roster-v1，一致性相对较好。

### 4.2 执行顺序与检查点
1. **基线**：运行帧探针和帧数据报告，跑一次平衡审计并保存对照。
2. **引擎扩展**（第一节的内容）和合成招式测试。门槛：在**不修改任何现有测试**的前提下，`tests/run_tests.ps1` 全部通过，84 个现有招式的帧数据报告前后一致。
3. **炭治郎数据**（先用占位片段）：
   - 8 个新招式资源；
   - 修改 `tanjiro_5A`、`tanjiro_jA`–`jD` 和 `tanjiro.tres`；
   - AI、界面、文档、发布验证扩展。

   完成后可以先实机试打和调数值。
4. **检查点 ①：定稿**。产出 3–4 个待机关键姿势候选、v3 设定图（四视图加头身标尺）、标准色卡，由用户选定。
5. **检查点 ②：待机循环**。用 MLS 补间做出待机循环，提供普通版和觉醒版的实机录像，由用户确认动作幅度。
6. **检查点 ③：试制批**。walk、stand_light、water_slash 三个片段走完整条管线，附质检报告，由用户确认画风后再批量生成。
7. **全量重绘**：
   - 范围：39 个普通片段 + 3 个回合片段 + 6 个新片段（约 70–85 次 CPA 调用，预留约 20% 的重抽；每次 40 秒到 2 分钟，按顺序执行）；
   - 后续：烘焙觉醒版、重建刀刃轨迹、替换占位片段、制作新招特效。
8. **检查点 ④：炭治郎整体确认**。产出全片段联系表、`tools/capture_tanjiro_vfx.gd` 录制的新旧招式（普通版和觉醒版）、平衡审计对比。用户确认后，再开始下一个角色（建议顺序：善逸 → 祢豆子 → 猗窝座）。

第 1–3 步不依赖美术，可以和第 4–6 步并行。

## 七、风险
- **生图漂移**：即使带了参考，CPA 仍可能出偏。质检门禁会拦下不合格的帧，并预留重抽额度；试制批（检查点 ③）先验证这一点。
- **特效对齐**：刀刃轨迹和特效对齐依赖新画面，需要重建轨迹并逐招复核。
- **手感变化**：前走中按 B/C 出 6B/6C、236B 出 6B、空中搓招出空中版，这些都已写进文档并加了测试。
- **AI 随机数**：只有炭治郎的 AI 随机数序列会变，平衡审计的数字会相应变化，按验收区间判断。
- **版权**：参考视频只用来参考招式构成和气氛，不描摹画面。
