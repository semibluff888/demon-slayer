# 鬼灭之刃 · 月下对决

Godot 4.7.1 / GDScript 制作的 2D 手绘动漫格斗游戏。支持炭治郎、善逸、本地双人和基础电脑对手，允许同角色对战。新版以月夜紫藤庭院、精细角色立绘、逐帧动作和水／雷特效构成统一美术。

## 启动

在 Windows 中双击 **`launch.cmd`**，或在 Godot 中导入 `project.godot` 后按 **F5** 运行项目。启动脚本使用本机引擎路径：

```text
D:\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64.exe
```

也可以从终端运行：

```powershell
& 'D:\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64.exe' --path 'J:\Project\demon-slayer'
```

默认窗口及逻辑界面 1280×720，支持 960×540 至 1920×1080 的连续缩放；非 16:9 窗口保留留边。战斗采用 60Hz 固定逻辑，场地宽 960 世界单位；1280×720 下人物倍率固定为 3.0，镜头只横向卷动。选择模式后分配角色与设备，点击“拔刀 · 进入对战”。界面可用鼠标、方向键、Tab、Enter，以及手柄十字键与确认键操作。

## 操作

| 动作 | 键盘 1 | 键盘 2 | 手柄（Xbox 布局标注） |
| --- | --- | --- | --- |
| 左右移动 | A / D | ← / → | 十字键 / 左摇杆 |
| 短冲刺 | 双击 A / D | 双击 ← / → | 双击左右方向 |
| 蹲下 | S | ↓ | 向下 |
| 跳跃 | W | ↑ | 向上 |
| 轻攻击 | F | J | X / 西侧面键 |
| 重攻击 | G | K | Y / 北侧面键 |
| 技能 | H | L | A / 南侧面键 |
| 投技 | R | U | B / 东侧面键 |
| 暂停 | Esc | Esc | Start |

键位按物理位置识别。选人页可以交换两组键盘或分配手柄；双人模式要求不同的设备条目。手柄断开时会自动暂停，重新连接后手动继续，也可返回选人切换到键盘。

- **防御**：相对对手后退可站防；蹲下＋后退可低防。站防能挡跳跃攻击，低防能挡蹲下攻击，两种防御都能挡中段。
- **短冲刺**：12 个逻辑帧内同方向按下两次，中间须松开。前冲 16 帧、后冲 14 帧；后撤仍面向对手。攻击、跳跃、蹲下和反向输入可立即衔接；冲刺没有无敌或自动防御。长按不会反复触发。
- **跳跃**：前跳和原地跳前翻、后跳后翻。空中轻／重攻击立即接入现有招式，收招后保持下落姿势直到落地。
- **背摔**：站立近身抓取，将对手过肩摔到身后，交换站位。抓取成功后第 20 帧摔落、扣 100 血，第 30 帧结束联动；版边会调整双人落点。空中或受击硬直中的目标不能被抓；同帧双投互拆，同帧打击可打断抓取。落空保留原有收招。
- **连段**：站立轻攻击 → 重攻击 → 技能。命中或被防后才能取消到下一段；空挥不能取消。蹲重为扫倒终结技。空中仅能轻／重攻击，落地有短暂硬直。
- **呼吸法**：“技能”与“前＋技能”分别释放两招，前方向根据角色朝向判定。
- **辅助**：F1 显示受击框（蓝）、攻击框（红）、身体阻挡框（绿）和状态；M 切换声音。

| 角色 | 技能 | 前＋技能 | 特色 |
| --- | --- | --- | --- |
| 灶门炭治郎 | 水面斩 | 水车 | 中距离斩击、向上迎击跳跃 |
| 我妻善逸 | 居合斩 | 霹雳一闪 | 更快步速、快速近身斩、长距离突进 |

## 规则

每局生命 1000、计时 60 秒，先赢两局获胜。超时按剩余生命判胜；超时同血与同时倒地均重赛该局，不增加胜局。命中停顿期间动作与回合计时暂停，但继续接受缓冲输入。技能有少量防御削血，削血不会直接击倒对手。正在进行的背摔结算完成后再判定超时或致命伤害。对战结束可再战、重新选人或返回主菜单。

电脑采用延迟 12 个战斗帧的可观察状态作决策，遵守同一套输入、硬直、距离与攻击规则。当前为单一普通难度。

动作按头部、手和肢体比例统一标定；翻身蜷体保留自然的姿势变化，不按外接框放大缩小。待机保持放松姿势，以约 3.2 秒一轮的轻微呼吸代替快速摆动，脚底固定，暂停时呼吸同步冻结。

镜头不随距离、跳跃或技能缩放。双方达到最大间距后，向外移动的一方会被挡住；地板、建筑、阴影与人物共享世界位移，静止人物保持站在同一块地砖上。

## 工程结构

- `scripts/arena_rules.gd`：场地宽度、固定倍率、身体边缘留量、最大间距、冲刺和投技时间常量。
- `scripts/combat.gd`：纯逻辑对战模型。`step([p1_command, p2_command])` 每次推进一个固定帧，同帧双方接触先收集再结算；没有场景或输入设备依赖。
- `scripts/fighter_state.gd`：角色位置、朝向、状态、判定框、硬直与输入缓冲。
- `scripts/move_data.gd`、`moves/*.tres`：11 份招式资源，配置启动／有效／收招、伤害、硬直、位移、击退与判定框。
- `scripts/input_router.gd`：两组键盘与手柄统一为操作指令；按下边沿与持续方向分开处理，防止长按不断重放招式。
- `scripts/ai_controller.gd`：有反应延迟、独立随机数状态的电脑控制器。
- `scripts/world_view.gd`：组织独立表现层、角色锚点、镜头、阴影和 HUD；显示帧率不会影响战斗逻辑。
- `scripts/presentation/`：角色图集播放、连续全景庭院、技能纹理与粒子、屏幕空间 HUD；固定倍率的横向镜头只约束身体可见范围。
- `scripts/ui/`：海报式主菜单、选人、操作指南、暂停和结算；原生按钮支持鼠标、键盘与手柄焦点。
- `scripts/main.gd`：菜单、设备分配、对局、暂停、结果和重开流程。
- `scripts/audio.gd`：启动时生成的短 PCM 音效，无需外部声音素材。

公共操作指令为 Dictionary：`x` 是 -1/0/1，`down` 是持续状态，`jump/light/heavy/skill/throw` 是单帧按下事件；可选 `dash` 为世界方向 -1/0/1，缺省 0。键盘和手柄由输入层统一识别双击，摇杆使用按下／释放双阈值过滤抖动。招式帧数均按 60Hz 计算，判定框以脚底为原点、向右定义，朝左时由逻辑镜像。修改帧数或判定框可直接编辑 `.tres` 资源。

角色、场景与特效通过 CPA / `gpt-image-2` 生成并经离线抠图、切片和图集整理，运行时全部从本地 `art/` 加载，无需联网或生图账号。每名角色 25 组动作、168 张不同画帧，起手／有效／收招严格对应现有招式时序。水流、电光、命中光与人物分开合成。

中文采用随工程分发的 Noto Sans SC / Noto Serif SC 字体子集（SIL OFL 1.1）。所有界面文字由 Godot 渲染，图片中没有菜单文案。联网、奥义／呼吸槽及其他角色不在当前版本中。本交付为可直接运行的 Godot 工程；独立发行版 EXE 需安装对应版本 Windows 导出模板后导出。

## 验证

```powershell
# 全部自动检查
.\tests\run_tests.ps1

# 同时打开渲染窗口，保存各页面截图到 artifacts/
.\tests\run_tests.ps1 -Capture

# 使用另一处 Godot
.\tests\run_tests.ps1 -Godot 'D:\path\Godot_console.exe'
```

测试包括战斗、输入和对局流程回归，真实鼠标点击／Tab／Enter／手柄焦点事件，以及完整美术、画帧覆盖、图集范围、透明底、动画阶段、连续受击、落地与视觉暂停检查。30／60／144 FPS 下分别运行同一段 1800 个物理帧的对局并比较状态摘要。

`-Capture` 保存实际 OpenGL 渲染的各页面、技能与同角色对战截图，输出 `artifacts/performance-hd.json`：1080p 下 1800 个 AI 对战渲染帧的平均、P95、P99 帧耗时及显卡信息，截图编码不计入性能采样。

新动作预览可用 Godot 加 `--fixed-fps 60 --script res://tools/capture_movement_preview.gd` 离线录制，随后用 `tools/encode_movement_preview.ps1` 编码为 MP4；`tools/build_art_gallery.py` 重建本地预览页。两者均不调用生图服务。原始输出尺寸以记录为准；当前场景使用一幅 4608×1152 连续全景，月亮、倒影、建筑和地面共享位移；原始服务返回尺寸记录在清单中。

手柄轴、死区、按键与混合设备完整比赛已用模拟输入验证；开发环境未连接实体手柄，实体设备体验仍需实机验收。游戏窗口和七种页面／战斗状态已通过 Godot 实际 OpenGL 渲染检查。

本次视觉修正可用 `--fixed-fps 60 --script res://tools/capture_visual_polish.gd` 重录，输出到 `artifacts/visual-polish/`。`tools/build_continuous_stage.py` 从已保存原图离线重建连续背景；无需再次生成图片。

## Git 提交范围

提交游戏源码、测试、构建工具、`art/` 成品资源、Godot `.uid` 和资源旁的 `.import` 设置，以及美术原图、提示词、标定、请求记录和清单。`output/imagegen/anime-v2/raw/` 是离线重建必需的原始素材，不是临时缓存。

不提交 `.godot/`、Python 虚拟环境与缓存、`artifacts/` 截图录像及备份、`output/imagegen/anime-v2/review/` 派生预览、临时文件和本地环境配置。预览可离线重建：

```powershell
python tools/build_movement_art.py
python tests/art_pipeline_tests.py --with-previews
```

默认美术检查验证仓库中的成品资源与来源，不要求本地预览存在；显式添加 `--with-previews` 时，预览缺失或损坏会导致检查失败。
